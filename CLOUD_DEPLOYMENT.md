# FinPilot AI — Cloud Deployment Guide

This guide walks through configuring the remaining cloud services. The code is
fully deployed on Vercel and the health endpoint confirms both functions are
live. What remains are cloud infrastructure credentials that require a paid
account (or free-tier signup) and cannot be generated by this project itself.

Current live state (verified 2026-09-10):

| Service    | URL                                              | Status                        |
|------------|--------------------------------------------------|-------------------------------|
| Frontend   | https://balamukunden-finpilot-ai-baymax5.vercel.app | ✅ Live                       |
| Backend    | https://finpilot-ai-one.vercel.app               | ⚠️ Health OK, DB missing      |
| AI service | Not deployed                                     | ❌ Container host required    |

## 1. MongoDB Atlas (free M0 cluster)

1. Sign up at https://www.mongodb.com/cloud/atlas (free tier).
2. Create a cluster (M0 Sandbox, any region).
3. **Database Access** → Add Database User:
   - Set username + a strong password (use `openssl rand -base64 24`).
   - Roles: **readWrite** on the `finpilot` database only (least privilege).
   - Never use the Atlas owner/admin account as the application credential.
4. **Network Access** — Vercel serverless functions have dynamic egress IPs,
   so Atlas cannot be restricted to fixed IPs. Opening the cluster to
   `0.0.0.0/0` is the **standard workaround, but it accepts ALL IPs** — it is
   NOT a hardened network boundary. This is an accepted limitation of the
   serverless architecture; it is mitigated by (a) the least-privilege
   `readWrite` DB user above and (b) a strong generated password. If your
   cluster already has a VPC peering/private-link option available to your
   backend, prefer that instead.
5. **Connect** → Drivers → copy the connection string, e.g.
   `mongodb+srv://<user>:<password>@<cluster>.mongodb.net/finpilot?retryWrites=true&w=majority`.
6. Set it on Vercel (see section 5).

## 2. Redis (Upstash — optional, recommended)

Distributed rate limiting across serverless instances; without it the app
falls back to per-instance in-memory limiting (still safe, just per-instance).

1. Sign up at https://upstash.com (free tier).
2. Create a Redis database.
3. Copy the `REDIS_URL` (`redis://default:...@...`).
4. Set it on Vercel (see section 5).

## 3. Object storage for receipts (Cloudflare R2 — free tier recommended)

1. Sign up at https://www.cloudflare.com/r2 (10 GB free).
2. Create a bucket, e.g. `finpilot-receipts`.
3. Create an API token with object read/write permission on that bucket.
4. Set `RECEIPT_STORAGE_*` on Vercel (see section 5).

## 4. Hosted LLM (OpenAI recommended)

1. Sign up at https://platform.openai.com and create an API key
   (or use Anthropic/another supported provider).
2. These vars go on the **AI service** deployment (not the Vercel backend):
   - `AI_PROVIDER=openai`
   - `LLM_API_KEY=<your key>`
   - `LLM_MODEL=gpt-4o-mini` (or your choice)
3. The AI service rejects Ollama/localhost in production by design.

## 5. Deploy the AI service (container host)

Requires a container host: Render, Railway, Fly.io, or Google Cloud Run.

### Render (free tier, easiest)

1. Create a new **Web Service** → connect your GitHub repo.
2. Root directory: `ai-service`, build command:
   `pip install -r requirements.txt`, start command:
   `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
3. Set env vars: `AI_PROVIDER=openai`, `LLM_API_KEY`, `LLM_MODEL`.
4. Deploy. Note the public URL, e.g. `https://finpilot-ai.onrender.com`.
5. Set `AI_SERVICE_URL=https://finpilot-ai.onrender.com` on the Vercel backend.

### Verify the AI service

`GET <ai_url>/api/health` must return 200 with `llm.configured: true`.

## 6. Add env vars to Vercel backend (`finpilot-ai` project)

```bash
vercel env add MONGODB_URI                   production --scope baymax5 --project finpilot-ai
vercel env add REDIS_URL                     production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_PROVIDER s3   production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_BUCKET        production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_REGION        production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_ENDPOINT      production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_ACCESS_KEY_ID production --scope baymax5 --project finpilot-ai
vercel env add RECEIPT_STORAGE_SECRET_ACCESS_KEY production --scope baymax5 --project finpilot-ai
vercel env add AI_SERVICE_URL                production --scope baymax5 --project finpilot-ai
vercel env add AI_SERVICE_KEY                production --scope baymax5 --project finpilot-ai
```

`AI_SERVICE_KEY` is already set — it must match the key used by the backend to
authenticate against the AI service. If the AI service enforces a key, set the
same value on its deployment.

After adding env vars, redeploy:

```bash
vercel redeploy https://finpilot-ai-one.vercel.app --yes --scope baymax5
```

## 7. Verify the complete flow

1. `GET https://finpilot-ai-one.vercel.app/api/health` → 200, no
   `configuration_required` status.
2. `GET https://balamukunden-finpilot-ai-baymax5.vercel.app/api/health`
   (same, via VITE_API_URL).
3. Register a user, log in, create a goal/transaction, upload a receipt,
   send a chat message — see the "Post-deployment smoke test" in
   `DEPLOYMENT_CHECKLIST.md`.

## Configuration matrix (production, Vercel backend)

| Var                                  | Required | Purpose                          |
|--------------------------------------|----------|----------------------------------|
| `MONGODB_URI`                        | Yes      | Database connection              |
| `JWT_SECRET`                         | Yes (set)| Access-token signing             |
| `JWT_REFRESH_SECRET`                 | Yes (set)| Refresh-token signing            |
| `CLIENT_URL`                         | Yes (set)| CORS allow-list for the SPA      |
| `COOKIE_SAME_SITE`                   | Yes (set)| `none` for HTTPS cross-site      |
| `COOKIE_SECURE`                      | Yes (set)| `true` for HTTPS-only cookies    |
| `AI_SERVICE_URL`                     | If AI    | Backend → AI service URL         |
| `AI_SERVICE_KEY`                     | Optional | Shared secret for AI calls       |
| `REDIS_URL`                          | Optional | Distributed rate limiting        |
| `RECEIPT_STORAGE_*` (7 vars)         | For uploads | S3/R2 receipt storage        |
| `ADMIN_EMAIL`/`ADMIN_PASSWORD`       | Optional | Seed admin account               |
